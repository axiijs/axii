# Changelog

Notable changes to axii, newest release first. Each entry says what changes for your code and how to migrate. Numbers in parentheses are pull requests in [axiijs/axii](https://github.com/axiijs/axii/pulls). Releases before 4.9.0 are not recorded here.

## 4.9.0 (unreleased)

4.9.0 is the result of a full audit of axii. Most entries are bug fixes, but many of them change what your pages render, so read **Breaking changes**, **Security** and **Dependencies** before upgrading. If you use server-side rendering, upgrade the server (`axii/ssr`) and the client (`axii`) together: `renderToString` output changed in several places, and `hydrateRoot` reports differences in older server HTML as mismatches and repairs them.

### Breaking changes

Code that relies on the old behavior needs changes.

- **`hydrateRoot` claims server nodes top-down, by position, and is no longer experimental.** Each host takes its own server nodes in document order, so hydration time grows linearly with the page. When server and client output differ, the difference is reported (`HydrationMismatchError`) and repaired: node structure, text and the attributes written by client props end up equal to a client render. Attributes that only the server wrote are removed on that repair path; elsewhere a leftover one is reported in development. While `hydrateRoot` runs, JSX returns a hydration description instead of a DOM node, and a description kept in a variable never becomes a node: after `const input = <input/>`, calling `input.focus()` in a click handler throws a `TypeError`, `input.value` is `undefined` and `input === ref.current` is `false` (development builds report such accesses with the JSX location). `RxList.map` rows and array items are replaced with the claimed nodes, and `createRoot().render()` is unchanged. This also replaces the interim claiming rules and the "experimental" label added during 4.9.0 development (#62). Migration: reach elements through `ref` (in the ref callback or in `useLayoutEffect`) instead of keeping JSX results and using them as nodes. (#55: #67, #80, #84, #89, #93)
- **`root.destroy()` keeps the listeners registered with `root.on()`.** After `destroy()` and a new `render()` on the same root, `error`, `attach`, `detach` and custom listeners still fire. Migration: code that registers a listener again after `destroy()` now has it twice, so drop the re-registration or pass the same function reference; to remove a listener, call the function that `on()` returns. (#63)
- **Errors thrown after a tree was destroyed are reported instead of thrown from `root.render()`.** Errors from a tree discarded in the middle of rendering, from a function child or list destroyed while it rendered, and from the cleanups of such a tree go to `configureDiagnostics({onError})` and the console, and one failing cleanup no longer stops the others; errors from a discarded tree inside a `Portal` no longer reach the parent root's `error` listeners. Migration: if you caught these errors around `root.render()`, observe them with `configureDiagnostics({onError})`. (#69)
- **Checkboxes: the `checked` prop decides whether the box is checked, and `value` is the submitted value.** `<input type="checkbox" value="red">` is no longer checked by default, a `null` or `undefined` `value` no longer unchecks the box, and once the element has a `checked` prop (even `checked={undefined}`) only that prop decides, whatever the prop order, so `checked={false} value={true}` and `checked={undefined} value={true}` are now unchecked; a boolean `value` still sets the state when there is no `checked` prop. Migration: express the checked state with `checked` and put only the submitted value in `value`; a wrapper component that forwards `checked` can no longer be checked with `value={true}`. (#48, #66)
- **A string entry in a `style` array sets only the properties it declares.** In `style={[{color: 'blue'}, 'margin-top: 3px']}` the client keeps `color`, as `renderToString` already did; a string `detachStyle` and `setAttribute(el, 'style', text)` behave the same way. Migration: if you relied on a string entry clearing earlier entries, remove those properties from the earlier entries or add a later object entry that sets them to `null`. (#92)
- **`<a>`, `<title>`, `<style>` and `<script>` written directly in an SVG element's JSX are SVG elements.** The SVG parent (not `<foreignObject>`, `<desc>` or `<title>`) re-creates them in the SVG namespace when it is created, which matches how the browser parses the server HTML. Migration: a reference to such a child taken before its parent was created points to the discarded HTML element, so use `ref`; a single such tag rendered later by a function child, a component or a list stays an HTML element, so create it with `createSVGElement`. (#72)
- **Props whose name starts with `on` are written only as event handlers.** Other `on*` names are no longer written as attributes; see the first entry under Security for the rule and the migration. (#64)
- **axii requires data0 `^2.17.0`.** See Dependencies. (#90)

### Security

- **A prop whose name starts with `on`, in any letter case, is never written as an attribute.** Only `on` followed by an uppercase letter (`onClick`) binds a listener; every other such name (`onclick`, `ONCLICK`, `once`, `online`, `onlyIcon`, `on-click`, SVG `xlink:onclick`) is dropped on every element, including SVG and custom elements, both on the client and by `renderToString`, so spreading an untrusted object (`<div {...untrusted}/>`) can no longer create an executable inline handler, and development builds warn once per name. A bare `on` attribute (AMP's `on="tap:…"`) is now written by the server too, and a name with invalid characters such as `"ON x"` is dropped instead of throwing `InvalidCharacterError` on the client. Migration: write events as `onClick={fn}` and data as `data-*` attributes; component props are not affected. (#64)
- **Hydration finishes a re-created element before inserting it.** When hydration replaces a server element that does not match, the new element gets its children and attributes while it is still detached, so a data script such as `<script type="application/json">` is no longer run as JavaScript, and `src`, `integrity`, `is` and `<select multiple>` behave as in a client render. No migration needed. (#76)
- **Stylesheet rules and `renderToString` keep a style value only if the browser reads it as exactly one declaration.** These paths write values into CSS text, so a value that could add declarations or rules is dropped, the same values a client-side inline style rejects: a top-level `;` or `!important`, unbalanced brackets or quotes, a malformed unquoted `url(…)`, a line break (`\n`, `\r`, `\f`) inside a string, a top-level `{}` block outside a custom property, or `url(` after `<!--`. To stay on the safe side, names with a non-ASCII character directly before `url(` and values nested more than 1024 levels deep are dropped too, and the server does not write an at-rule key whose prelude contains a top-level `;`. Valid values that used to be dropped, such as `url(a}b.png)` or a `}` inside a comment or an escape, now work. No migration needed. (#48, #81)
- **`renderToString` refuses markup it cannot write safely.** It throws on attribute names and tag names the DOM would reject (an untrusted key such as `x onmouseover=…` in a spread, a dynamic tag name), on `<script>` text that cannot be serialized safely, and on `<plaintext>` in HTML content; `<style>` and `<script>` text inside `<svg>` or `<math>` is escaped as ordinary text, so it can no longer turn into real elements when the browser parses the page. Migration: validate untrusted prop keys and tag names before rendering them. (#48)

### Behavior changes

These need no code changes in most apps, but what is rendered differs. Tests that compare DOM or server HTML strings may need updates.

#### Roots, effects and lifecycle

- **`root.render()` and `root.destroy()` no longer belong to the effect that calls them.** Inside an `autorun` or `computed`, atoms read while the root's content renders or is torn down (component bodies, `useEffect` callbacks and cleanups, `ref(null)`) no longer subscribe that effect, so a "destroy, then render" `autorun` no longer re-runs when they change, and bindings and effects created there are no longer destroyed when that effect re-runs: the content lives until `root.destroy()`. No migration needed; if the effect should re-run on such an atom, read it in the effect itself. (#47)
- **A function child no longer tracks the teardown of its old content.** Atoms read in cleanups (`useEffect` and `useLayoutEffect` cleanups, `onCleanup`, `ref(null)`, a function `detachStyle`) no longer re-run the function child, which removes an endless remount loop when new content writes an atom that the old content's cleanup reads, and effects created in those cleanups survive the next re-run. No migration needed. (#47)
- **`root.dispatch()` runs its listeners untracked.** Reads inside `attach`, `detach`, `error` and custom listeners no longer subscribe the effect that called `root.dispatch(...)`, and effects created in listeners, including the layout effects and refs run on `attach`, are no longer collected by that effect; `error` listeners also run detached from the failing binding. No migration needed. (#47, #48)
- **List row cleanups run while the row is still in the document, and a replaced row is torn down before its replacement is mounted.** This applies to `splice`, `pop`, `shift`, `clear` and `set`: a ref shared by the old and the new row ends up on the new row, and nodes a row cleanup inserts into the list's parent are kept. No migration needed. (#48, #69)
- **A root rendered in a component body and `Portal` content with `destroyOnUnmount={false}` stay fully live until their own root is destroyed.** Before, their attribute bindings and lists stopped updating when the component unmounted while their text kept updating. No migration needed. (#48)
- **Calling `root.destroy()` again during destruction is safe.** From a cleanup or a `detach` listener it dispatches `detach` only once and no longer overflows the stack, rendering into the same root from such a cleanup works, and `detach` listeners can still read `root.host`. No migration needed. (#48, #69)
- **Nodes from another realm and any `Element` are accepted as content.** A node from a same-origin iframe can be a component's return value, a function child's value, an array item, a JSX child or a list row, and any `Element` (MathML, for example) is accepted where only HTML and SVG elements were; a plain object such as `{nodeType: 3}` used as a child now throws a `TypeError` instead of `unknown child type`. No migration needed. (#69)
- **A controlled `<select>` whose selected `<option>` is removed shows what a fresh render shows** (no selection when nothing matches), also when the option leaves with an exit animation. No migration needed. (#48, #69)

#### DOM attributes and forms

- **`false` is no longer written as the string `"false"`, and `true` writes an empty attribute, on string-typed properties of built-in elements.** `title={false}` and `href={cond && '/x'}` write nothing, `<div popover>` is an auto popover, `<a download>` no longer names the file `true`, and `draggable="false"` and `translate="no"` are no longer turned into `true`; `aria-*` and `data-*` attributes still write `"false"`. Migration: pass the string `"false"` where an attribute must literally read `false`. (#48)
- **camelCase SVG attributes take effect.** A camelCase name whose dashed form is an SVG presentation attribute (`fillRule`, `clipRule`, `stopColor`, `textAnchor` and so on) is written dashed and can be removed again; before, only nine prefixes were converted and the rest were silently ignored, while native camelCase attributes such as `viewBox` stay as they are. No migration needed, but check graphics whose previously ignored attributes now apply. (#48)
- **`data-*` attributes keep the name you wrote, static or reactive, and arrays are written whole.** A reactive `data-item_id` is no longer written as `data-item-id` and a reactive `data-fooBar` is written like the static one (`data-foobar`, since HTML attribute names are lowercase), and a static `data-ids={[1, 2]}` is written as `"1,2"` instead of only its last item. Migration: update selectors and test ids that matched the old names. (#48)
- **`dangerouslySetInnerHTML={{__html: string}}` works on the client.** It used to render `[object Object]`; a function or atom returning `{__html}` works too, and hydration keeps the server markup. No migration needed. (#65)

#### Styles

- **In a `style` array, later entries win for top-level declarations.** An entry that needs a stylesheet (nested selectors, at-rules, `animation` or `@keyframes`, a `bindProps` style) takes the top-level properties it declares back from the inline values that earlier entries wrote, so `[{color: 'blue'}, {color: 'red', '&:hover': {…}}]` is red; on the server this also removes declarations from earlier string entries. Known limitation: an earlier inline value still beats a nested rule in a later entry (`[{color: 'red'}, {'&:hover': {color: 'blue'}}]` never turns blue). No migration needed; "Style arrays" in the README shows the recommended patterns. (#48, #77)
- **`setAutoUnitType` also applies to stylesheet rules and to `renderToString`,** which always used `px` before. Migration: if you call `setAutoUnitType('rem')` or `setAutoUnitType('em')` and relied on `px` in nested rules, write the unit explicitly. (#48)
- **136 standard length properties get an automatic unit instead of 36.** A number on properties such as `borderTopLeftRadius`, `outlineOffset`, `inset*`, `scrollMargin*`, `translate`, `gridTemplateColumns` and `verticalAlign` used to be written without a unit and dropped by the browser; it now gets the unit in inline styles, stylesheet rules and server output alike, `0` is written as `0px` (same computed value, but server style text and content-addressed style ids change), and the exported `AUTO_ADD_UNIT_ATTR` matches the same names. On these properties a non-`StyleSize` object no longer gets a unit appended (`"2rem"`, not `"2rempx"`), `new Number(5)` writes `"5"`, stylesheet rules and server output add the unit to a `bigint`, and a `Symbol` value in an inline style no longer throws. No migration needed. (#91)
- **Array values are joined the same way on every path.** `[300, 'ms']` is written as `300ms` (was `300,ms`), and custom properties follow the same rules as other values on the client and the server: `{'--gap': [4, 8]}` is `4 8` and `{'--t': [300, 'ms']}` is `300ms`, with no unit added to numbers. No migration needed. (#48, #92)
- **Stylesheet rules and server output name properties the way inline styles do.** `cssFloat` and lowercase vendor prefixes such as `webkitLineClamp` now work there; a bracket left open at the end of a value, which an inline style closes automatically, drops the declaration there. No migration needed; close brackets yourself. (#48)

#### Server rendering (`renderToString`)

- **Components go through the same props pipeline as on the client.** propTypes defaults, `bindProps`, `as` and `$name:` overrides now apply on the server, and attribute values are evaluated as on the client (reactive attribute functions are called, `checked={atom(false)}` no longer writes `checked`, a `className` array writes its class names), so server HTML matches the client. No migration needed. (#48)
- **Attributes are written the way the client leaves them.** A real boolean attribute set to `true` is written `x=""` (was `x="true"`), a numeric property set to `true` writes `"1"` (`tabIndex`), `0` and `""` on a boolean property are omitted, and `disabled` with any truthy value is still `"true"`; `defaultValue`, `defaultChecked`, `defaultSelected` and `defaultMuted` are written as `value`, `checked`, `selected` and `muted` (a `<textarea>`'s `defaultValue` as its text), global properties on custom elements are written as given (`title={false}` becomes `title="false"`), `<div htmlFor>` keeps its name, and `nonce={true}` is `"true"` (was `""`). On the client, clearing `ch`, `chOff` or `encoding` no longer leaves `char`, `charoff` or `enctype` behind. No migration needed; update tests that compare server HTML strings. (#70)
- **A function child of `<textarea>`, `<title>`, `<style>` or `<script>` writes its current text,** so `<title>Inbox ({count})</title>` renders on the server, and it throws `a function child of <tag> must return text` only when it returns structure. No migration needed. (#48, #72)
- **`<table>` gets an implied `<tbody>` only when its direct children include bare `<tr>` and no section element,** so a function, list or array that renders `<tbody>` or `<thead>` no longer leaves an empty `<tbody>`; inside SVG, the attributes of `<a>`, `<title>`, `<style>` and `<script>` are written with SVG rules. No migration needed. (#72)
- **A list row whose descendant has `detachStyle` is followed by `<!--rx list item-->`, as on the client,** so such pages hydrate (they used to throw). No migration needed. (#71)
- **Function children whose value is a function, an `RxList` or a `reusable` are written in the client's shape,** without the extra `<!--axii:0-->` or `<!--unhandledChild-->`, and an empty atom in an array writes no `<!--axii:0-->`, so these shapes hydrate without leftover nodes or errors; a function child returning an unsupported value now throws `unsupported render source` instead of `unsupported child type`. No migration needed. (#83)
- **Holes in sparse arrays (`[a, , b]`) are skipped as on the client,** while explicit `undefined` and `null` items still render as empty; on the client, an array whose first slot is a hole is now removed, replaced or moved as a whole (its content used to stay behind). Migration: upgrade server and client together; HTML from an older server is reported as a hydration mismatch at each hole and repaired. (#87)
- **`{__html: null}` and `{__html: undefined}` in `dangerouslySetInnerHTML` write empty content** instead of the text `null` or `undefined`. No migration needed. (#65)
- **When a later `style` entry overrides an `!important` declaration in an earlier string entry, the server no longer writes that `!important` declaration.** No migration needed. (#92)

### Fixes

No migration needed.

- `lazy()` components are transparent: `ref` receives the loaded component and `$name:` configuration reaches it. (#48)
- A component or function child may return a `Comment` or `Text` node; it used to throw `unknown child type`. (#48)
- Nested arrays in `style`, `className` and event handler props are flattened; they used to throw or write indexes such as `class="card 0 2"`. (#48)
- `onGotPointerCapture` and `onLostPointerCapture` fire. (#48)
- A nested rule under a selector list applies to every selector in the list (`'&.a, &.b': {'& span': {…}}`). (#48)
- The `animation` shorthand no longer resets `animation-*` longhands written after it, and a `null` item in an `animation` array no longer voids the whole declaration. (#48)
- `null`, `false` and `undefined` clear object-typed properties such as `srcObject` and `valueAsDate`, and `relList={null}` no longer leaves `rel=""`. (#48)
- A prop with a propTypes default is no longer overwritten by a bound prop that evaluates to `undefined`. (#48)
- `PropTypes.atom`, `rxList`, `rxSet` and `rxMap` have `check` (alone they rejected every value, and inside `oneOfType` they threw), `PropTypes.map({...}).check(null)` no longer throws, and `PropTypes.number.parse` throws on input such as `'abc1'` or `'1px'` instead of returning `NaN`. (#48)
- `Form`: when one of several fields with the same name unmounts, or a list row is replaced, the value of the field that is still mounted is kept. (#48)
- `RxDOMDragState`: a plain click no longer dispatches `dragend`; a drag interrupted by unmounting or destroying gets exactly one `dragend` carrying the last state and leaves no listeners behind. (#48)
- `RxDOMFocused` updates again after its element is remounted, and `RxDOMSize` on a non-replaced inline element reports 0 consistently instead of a measured size that later drops to 0 (development builds suggest giving the element a box). (#48)
- A `splice` that inserts more than about 100,000 rows no longer throws `RangeError`. (#48)
- Content that a function child, a list or a root was still rendering when it got destroyed no longer leaks or ends up in the container. (#48)
- A function child whose old content's cleanup destroys it no longer renders again or throws an uncaught `TypeError`, and a row cleanup that destroys its list runs each row's cleanup exactly once. (#48)

### Performance

No migration needed.

- Mounting and clearing many rows with different nested styles is no longer quadratic: stylesheet writes from the same synchronous work are merged (4,000 rows: mount 1,606 ms → 45 ms, clear 1,579 ms → 3.7 ms). (#48)
- Swapping two rows of a list costs in proportion to the rows that move, not to the span between them (200,000 rows, swapping first and last: 6.2 ms → 0.0015 ms). (#48)

### Dependencies

- **axii requires data0 `^2.17.0`** (the peer dependency was `^2.16.0`). axii re-exports data0, so these data0 2.17.0 fixes are visible through axii: reads in cleanup code no longer create dependencies; an error in a cleanup no longer stops destruction (the first error is thrown, later ones go to `console.error`); a `computed` whose recomputation failed keeps the dependencies of the failed run, so it retries when they change; the `onCleanup` option of `RxList.map` also runs when a row's value is recomputed and replaced; `RxMap.values()` and `entries()` no longer emit `undefined` for a deleted key first; `sortSelf` puts `undefined` last. Migration: install data0 `^2.17.0`, and adjust code that relied on the old behavior, for example code that assumes the `onCleanup` option of `RxList.map` runs only when a row is removed. (#90)

- Refactors and performance work without visible behavior changes: (#74), (#75), (#86).
